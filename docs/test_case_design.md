# TaskFlow 测试用例设计

> 用例总数:**64**(API 55 + UI 9),全部采用 `@allure.title` 中文标题,报告中可直接阅读。

## 1. 用例设计方法

- **等价类 + 边界值**:所有入参字段按"合法等价类 / 非法等价类 / 边界值(3 点法)"设计
- **状态机路径覆盖**:pending → in_progress → done 全路径 + 非法流转 + 终态保护
- **数据驱动**:边界值与非法入参集中维护在 `testdata/users.yaml`、`testdata/tasks.yaml`,一条用例覆盖一组数据
- **双重断言**:本地模式在接口断言之外直连临时 SQLite 做落库断言,验证"响应正确 + 持久化正确"
- **UI 层价值聚焦**:UI 只测前端真实行为(渲染、竞态、表单交互、路由守卫),业务规则断言留给 API 层

## 4. 性能场景(4 个)

| 场景 | 权重 | 说明 |
|------|------|------|
| 查询任务列表 | 4 | 高频只读场景 |
| 创建任务 | 2 | 中频写入 |
| 查询统计 | 1 | 低频只读 |
| 任务生命周期 | 1 | 低频全链路:创建→完成→删除 |

每个虚拟用户 `on_start` 独立注册/登录,携带 JWT 会话,模拟真实用户行为;等待时间 1-3s 随机分布。

## 5. 用例执行与隔离原则

1. **用户级隔离**:每个用例独立随机用户(时间戳+随机串),不依赖执行顺序,可任意重跑
2. **客户端级隔离**:已登录场景使用独立 ApiClient 实例,token 不跨用例污染(鉴权用例的核心前提)
3. **服务级隔离**:本地模式每个执行会话(并行时每个 worker)独立临时数据库 + 独立端口
4. **可重复性**:全部用例设计为幂等 —— 失败重跑、定时回归不产生脏数据
5. **外部服务降级**:落库断言依赖临时数据库直连,外部服务模式下自动 skip,响应断言不降级
