# TaskFlow 自动化测试计划

## 1. 测试目标

针对自建任务管理系统 **TaskFlow**,建设一套可持续迭代的自动化测试体系,达成:

1. **功能回归**:核心业务(认证、任务 CRUD、状态机、统计)接口级自动化,回归周期 ≤ 1 分钟
2. **用户体验**:关键用户旅程(登录注册、任务全生命周期)UI 级自动化,失败可截图/回放诊断
3. **质量左移**:自动化用例发现并修复被测系统缺陷,形成闭环
4. **可交付**:CI 全自动执行,Allure 报告在线可访问,支持容器化一键运行

## 2. 测试范围

### 2.1 范围内

| 模块 | 功能点 | 自动化层级 |
|------|--------|-----------|
| 认证 | 注册、登录、当前用户、token 校验(无/伪造/过期) | API |
| 任务 | 创建、查询列表/详情、更新、删除、状态流转 | API + UI |
| 权限 | 数据隔离(横向越权)、未登录访问(纵向越权) | API |
| 统计 | 汇总看板、完成率 | API + UI |
| 登录/注册页 | 登录成功/失败、注册流程、重定向、退出 | UI |
| 任务主页 | 创建/开始/完成/编辑/删除、筛选、统计联动、异常交互 | UI |
| 性能 | 列表查询、创建、统计、生命周期(4:2:1:1 权重) | Locust |

### 2.2 范围外

- 密码找回、邮箱通知(未实现)
- 多用户并发写同一任务(后端为单写模型,不涉及)
- 浏览器兼容性矩阵(仅 chromium;多浏览器可通过 pytest-playwright 参数化扩展)

## 3. 测试策略

### 3.1 分层策略

采用测试金字塔模型:

- **接口层(主体,55 例)**:业务规则、边界值、异常、权限在 API 层穷举 —— 快、稳、定位精确
- **UI 层(关键旅程,9 例)**:只验证"用户能走通的核心路径"与"前端真实交互行为",数据预置走 API,不重复接口层已覆盖的业务断言
- **性能层(4 场景)**:独立脚本、手动/CI 触发,不与功能回归混跑

### 3.2 环境策略

| 环境 | 被测服务 | 用途 |
|------|---------|------|
| local | 框架自动拉起 uvicorn 子进程 + 临时 SQLite | 日常开发、本地回归 |
| test | 独立部署的服务(TEST_BASE_URL 指定) | 预发布验证 |
| ci | docker-compose 中的 app 容器 | CI 流水线 |

关键设计:**local 环境零前置** —— 开发者克隆即跑,不需要手动部署任何东西。

### 3.3 数据策略

- 每个用例注册独立随机用户(时间戳 + 随机串),用例间数据完全隔离
- 边界值数据集中维护在 `testdata/*.yaml`,支持数据驱动
- 本地模式可直连临时数据库做**落库断言**(接口响应 + 持久化双重验证)

### 3.4 稳定性策略

- 自动等待:UI 断言全部使用 playwright auto-waiting(默认 5s),杜绝 sleep
- 失败重试:CI 中 `--reruns 1`,过滤环境抖动
- 失败诊断:截图(全页)+ Trace(逐步回放)+ 执行日志,全部归档进 Allure
- 并行执行:按 worker 端口偏移,各 worker 独立服务 + 独立数据库,互不干扰

## 6. 缺陷记录(自动化测试发现并修复)

自动化用例直接发现被测系统 **8 个真实缺陷**,全部修复并回归通过:

| # | 缺陷描述 | 严重级别 | 发现用例 | 根因 |
|---|---------|---------|---------|------|
| BUG-01 | 快速切换筛选 tab,旧请求响应晚于新请求返回,列表被旧数据覆盖 | 高 | UI:筛选交互 | 前端无请求竞态保护 |
| BUG-02 | 统计看板在快速操作时显示过期数据 | 高 | UI:统计联动 | 统计请求无竞态保护(同上机制) |
| BUG-03 | 连续快速添加任务时,中间输入的内容丢失(3 次输入只创建 2 个任务) | 高 | UI:连续创建 | 提交后等响应返回才清空输入框,覆盖了用户新输入 |
| BUG-04 | 注册成功后提示语立即被清空,用户看不到"注册成功" | 中 | UI:注册流程 | 先写提示后切 tab,切 tab 逻辑清空了提示区 |
| BUG-05 | 任务状态枚举落库为大写(`PENDING`),与接口契约小写不一致 | 中 | API:落库断言 | SQLAlchemy Enum 未配置 values_callable |
| BUG-06 | 前端 `$` 工具函数误用 CSS 选择器,筛选按钮点击报 `$ is not defined` | 中 | UI:筛选 | testid 辅助函数与 jQuery 语法混淆 |
| BUG-07 | 登录按钮缺失 id 定位属性,自动化可定位性差 | 低 | UI:登录 | 前端元素未考虑可测性(data-testid 缺失) |
| BUG-08 | 创建任务失败后用户输入被清空,需重新输入 | 低 | UI:异常交互 | 错误分支未恢复输入框内容 |
| BUG-09 | 容器内 UI 用例全部 ERR_SSL_PROTOCOL_ERROR(环境缺陷,非被测系统问题) | 中 | 全部 UI 用例 | 新版 Chromium 默认 HTTPS-Upgrade 将 http://app:8001 升级为 https://, TLS 握手打到纯 HTTP 服务;另发现 compose 持久化 volume 导致跨运行数据残留 |

> 这正是本项目最值得写进简历的部分:**不是"写用例跑别人写好的系统",而是"用自动化用例做了一次真实的质量改进"**。
>
> BUG-09 属于测试环境兼容性问题,典型排查思路:请求日志对比(同 URL 出现 http/https 两份请求)→ 定位浏览器行为 → `*.localhost` 域名豁免 + host-resolver-rules 修复(与浏览器版本无关,优于临时 feature 开关)。

## 7. 风险与应对

| 风险 | 应对 |
|------|------|
| UI 用例对前端改版敏感 | data-testid 稳定定位 + POM 单点维护 |
| 并行执行端口冲突 | worker 端口偏移机制(已内置) |
| CI 浏览器依赖安装慢 | 缓存 playwright 浏览器路径;Docker 分层缓存 |
| 外部服务模式无法做落库断言 | 用例自动 skip,本地模式保留深度断言 |
